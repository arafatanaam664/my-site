# انتقال alshafra.com إلى المنصة الجديدة

**المبدأ:** ينتقل النطاق إلى منصة Alshafra الجديدة بالكامل، من دون نقل كود أو قالب أو هوية أو محتوى الموقع السابق. وتستخدم إعادة التوجيه فقط عندما توجد وجهة جديدة تؤدي الوظيفة نفسها بصورة حقيقية.

> لا ينبغي تحويل صفحة قديمة إلى الصفحة الرئيسية أو إلى قسم عام لمجرد الاحتفاظ بإشارة بحث. إذا لم توجد وجهة مكافئة، فالأصح إنشاء صفحة جديدة أصلية ومراجعة أولًا، أو إرجاع `410 Gone` للمسارات المتروكة عن قصد.

| `/about` و`/contact` و`/privacy` و`/terms` | نفس المسارات | صفحات قانونية ومعلوماتية جديدة على المسار نفسه. |

## المسارات التي لا تحول في الإصدار الأول

تظهر خريطة الموقع القديمة صفحات للمواعيد والرواتب والعد التنازلي والأسعار والعملات، إضافة إلى صفحات «رائجة» متشعبة. لا تحول هذه الصفحات تلقائيًا إلى `/calendar` أو `/articles` لأن الإصدار الجديد لا يقدم بعد بديلاً مكافئًا لها. تتحول فقط بعد إنشاء صفحة أصلية جديدة بمصدر وحالة وتاريخ مراجعة. وحتى ذلك الحين، يعاد للمسارات المتروكة عن قصد `410 Gone`، كي لا تبدو كصفحات حية أو تحوّل الزائر إلى نتيجة مضللة.

## قائمة تحقق قبل تحويل النطاق

| الإجراء | معيار الإنجاز |
|---|---|
| ربط alshafra.com بالمشروع المنشور | سجل DNS وشهادة TLS صالحة، مع إعادة توجيه `www` حسب إعداد النطاق. |
| اختبار التحويلات | تتحول المسارات المعتمدة بـ301 إلى الوجهة الصحيحة، وتعيد المسارات المتروكة 410 بدل 302 أو الصفحة الرئيسية. |
| اختبار SEO | canonical و`og:url` و`sitemap.xml` تشير إلى `https://alshafra.com` فقط. |
| مراقبة الانتقال | مراجعة أخطاء 404/410 وطلبات الزحف وصفحات الدخول الفعلية قبل إضافة تحويلات جديدة. |
| تعطيل الموقع السابق | لا يتم إلا بعد التحقق من أن المشروع الجديد يعمل على النطاق ويمر من اختبارات الجودة. |
