# AL SHAFRA MASTER BLUEPRINT

**الإصدار:** 1.0  
**الحالة:** معتمد كأساس بناء النسخة الأولى  
**المبدأ الحاكم:** Alshafra منصة عربية مستقلة للمعلومات العملية والأدوات والأدلة؛ التقويم والمواعيد وحدة قوية داخلها وليسا العلامة أو نقطة تعريف المنتج.

## 1. الرؤية والهدف

تساعد Alshafra المستخدم العربي على الانتقال من سؤال عملي إلى خطوة واضحة: يحسب أو يحول أو يتابع موعدًا، ثم يجد دليلًا موثوقًا يشرح الاستثناءات، ثم يكتشف موارد مرتبطة تفيده. لا تُعرّف المنصة نفسها بوصفها مجمع روابط أو آلة إنشاء صفحات أو موقع تقويم موسعًا.

ينصب هدف الإصدار الأول على بناء تجربة سريعة وموثوقة وقابلة للفهرسة، مع أساس إدارة محتوى ومراجعة مصادر يمكنه التوسع لاحقًا. النمو العضوي وإيرادات الإعلانات نتيجة لفائدة المنتج وثقة المستخدم، لا غاية تبرر تخفيض الجودة أو تضليل المستخدم.

## 2. الأهداف وغير الأهداف

| النوع | القرار |
|---|---|
| أهداف الإصدار الأول | إطلاق أدوات عملية، تقويم ومواعيد موثقة، أدلة ومقالات أصلية، بحث وتنقل وربط داخلي، وواجهة عربية RTL متجاوبة. |
| أهداف التشغيل | إدارة المحتوى والمصادر والصلاحيات وسير النشر، مع تحليلات واقعية لا تعرض أرقامًا مصطنعة. |
| أهداف SEO | صفحات قابلة للفهرسة لها نية واضحة، metadata مركزية، canonical وsitemap وrobots وJSON-LD صحيح. |
| غير أهداف الإصدار الأول | شبكة اجتماعية، مجتمع مفتوح، وظائف ومنح وفرص، أخبار عامة، سفر، مقارنات، فهرس تطبيقات، توصيات بالذكاء الاصطناعي، حسابات مستخدمين عامة، أو نشر آلي لمحتوى واسع. |
| قيود صريحة | لا كود ولا هوية ولا روابط ولا محتوى منسوخ من الموقع السابق. لا قسم علني بلا محتوى موثوق. لا تقييمات أو شهادات أو أرقام تفاعل مختلقة. |

## 4. نموذج القيمة والهوية

> **وعد المنتج:** «معلومة أو أداة مفيدة، بصياغة عربية واضحة، في صفحة سريعة تعرف ما تقوله ومتى تم تحديثه.»

هوية Alshafra هي هوية معرفة عملية هادئة وليست هوية حكومية ولا هوية تقويم. يقترح النظام البصري اتجاه **محرر عملي أنيق**: خلفيات عاجية دافئة، نص فحمي داكن، أخضر مزرق عميق كلون ثقة، ولمسة نحاسية محدودة للحالات والتنبيهات. يركز التصميم على المساحات البيضاء، هرميات عربية مقروءة، أيقونات وظيفية، وبطاقات تستخدم عند الحاجة فقط.

| عنصر النظام البصري | قرار الإصدار الأول |
|---|---|
| الطباعة | خط عربي واضح للقراءة الطويلة، مقياس نص متدرج، وارتفاع سطر مريح على الهاتف. |
| الألوان | نظام رموز موحد للحالات والأزرار والروابط والتنبيه، لا ألوان عشوائية لكل قسم. |
| المكونات | رأس صفحة، تنقل رئيسي، بحث، Breadcrumbs، بطاقات محتوى، بطاقات أداة، جدول مواعيد، صندوق مصدر، محتوى ذو صلة، وحالات فارغة وخطأ. |
| الحركة | انتقالات قصيرة وظيفية فقط، مع احترام تقليل الحركة، ومن دون مؤثرات تبطئ القراءة. |

## 6. نموذج المحتوى والبيانات

يبني النظام حول سجل محتوى موحد قابل للتوسع، لا حول جداول منفصلة متشابهة لكل نوع. يحمل كل سجل نوع المحتوى وحالته ومصدره وموضوعه ونطاقه الجغرافي الاختياري ووقت مراجعته وعلاقاته بالصفحات الأخرى.

| الكيان | الغرض | حقول أساسية |
|---|---|---|
| Section | إدارة الأقسام وترتيبها وظهورها | الاسم، slug، الوصف، الحالة، الترتيب، إعدادات SEO. |
| ContentItem | دليل أو مقال أو صفحة هبوط أو FAQ | النوع، العنوان، slug، الملخص، النص، الحالة، المؤلف، المنشور والمراجع، القسم. |
| ToolDefinition | أداة عملية قابلة للاختبار | الاسم، slug، مدخلات التحقق، إصدار المنطق، وصف النتيجة، دليل مرتبط. |
| CalendarEvent | موعد أو مناسبة | العنوان، النوع، تاريخ البداية والنهاية، البلد الاختياري، الحالة، المصدر، وقت المراجعة، مستوى الثقة. |
| Source | مصدر رسمي أو تحريري | الجهة، الرابط، نوع المصدر، تاريخ الاطلاع، ملاحظات الموثوقية. |
| Tag وTopic | فهم موضوع المحتوى وربطه | الاسم، slug، الوصف، الأولوية. |
| SeoRecord | بيانات فهرسة مركزية | URL، title، description، H1، canonical، indexability، نوع JSON-LD. |
| RelatedLink | روابط داخلية مقترحة أو معتمدة | الصفحة المصدر، الوجهة، النوع، السبب، درجة الصلة، الحالة. |
| ContentRevision | مراجعة وتدقيق المحتوى | رقم الإصدار، المراجع، التغيير، وقت المراجعة، قرار النشر. |

## 7. نظام الإدارة والصلاحيات وسير النشر

تُفصل الواجهة العامة عن لوحة الإدارة. تستخدم الواجهة العامة تنقلًا موجهًا للمحتوى، بينما تستخدم الإدارة لوحة جانبية محمية ولا تظهر لمحركات البحث.

| الدور | الصلاحيات الأساسية |
|---|---|
| Super Admin | المستخدمون، الأدوار، الإعدادات الحساسة، مصادر البيانات، سجل التدقيق. |
| Admin | إدارة الأقسام والمحتوى والمصادر والـSEO وسير النشر. |
| Editor | مراجعة وتحرير ونشر المحتوى في نطاقه، من دون إدارة الصلاحيات أو الإعدادات الحساسة. |
| Author | إنشاء المسودات وتحرير ما يملكه وإرسالها للمراجعة. |
| Analyst | قراءة التحليلات وسجلات الجودة فقط. |

```text
Draft → In Review → Approved → Published → Archived
```

لا ينتقل المحتوى الحساس للوقت من مسودة إلى منشور إلا بوجود مصدر ومراجع وتاريخ مراجعة. وينشئ كل نشر نسخة مراجعة وسجل تدقيق، وتبقى عمليات الحذف قابلة للتحويل إلى أرشفة أو 410 حسب سياسة URL واضحة.

## 8. SEO والربط الداخلي

يُدار SEO من مصدر مركزي، لا من عناوين موزعة في المكونات. تشتق كل صفحة عامة title ووصفًا وH1 وcanonical وحالة فهرسة ونوعًا صحيحًا من JSON-LD. وتحمل الصفحات التي لا تمثل وجهة بحث مستقلة، مثل البحث والصفحات الداخلية والإدارة، `noindex`.

ينفذ الربط الداخلي على ثلاثة مستويات: هرم القسم وصفحاته، روابط سياقية ضمن الدليل أو المقال، ووحدة محتوى ذي صلة تعتمد على الموضوع والنوع والجمهور وقوة العلاقة. ولا يضاف رابط إلا إذا كان يجيب عن حاجة تالية منطقية؛ كما تمنع عملية التحقق روابط الأقسام المؤجلة والصفحات المكسورة والوجهات غير المفهرسة بلا مبرر.

## 9. المعمارية التقنية

| الطبقة | القرار | السبب |
|---|---|---|
| الموقع العام | React مع عرض خادمي للصفحات العامة ثم Hydration محدود | تسليم HTML بمحتوى وmetadata حقيقيين للزائر ومحركات البحث. |
| لوحة الإدارة | React محمية بعد المصادقة | إدارة سير المحتوى والصلاحيات من دون تعريض بيانات خاصة في HTML العام. |
| الخادم | Express + tRPC | واجهات برمجية بعقود نوعية موحدة بين العميل والخادم. |
| قاعدة البيانات | MySQL عبر Drizzle | محتوى وعلاقات ومراجعات وصلاحيات وبيانات تحليلية وصفية. |
| التخزين | تخزين كائنات للوسائط مع Metadata في قاعدة البيانات | تجنب تخزين الملفات الثنائية داخل الجداول. |
| البحث | بحث مبدئي في المحتوى المنشور مع تطبيع عربي بسيط | حل خفيف قابل للتوسع دون إدخال بنية بحث ثقيلة مبكرًا. |
| الأداء | HTML عام مع عرض خادمي، صور محسنة، تحميل كسول، وJavaScript حسب الحاجة | ملاءمة للهاتف والفهرسة وتجربة الإعلان. |

تُحوّل الواجهة العامة من القالب العميلي الحالي إلى عرض خادمي قبل إطلاق الصفحات القابلة للفهرسة. تحافظ الصفحات العامة على metadata فريدة و404 حقيقية وcanonical وتعرض المحتوى في HTML الأولي. وتبقى الإدارة والبحث الداخلي والحسابات صفحات محمية أو `noindex` حيث يلزم.

## 10. التحليلات والإعلانات والخصوصية

تسجل التحليلات أحداثًا وظيفية مثل مشاهدة الصفحة، فتح نتيجة بحث، استخدام أداة، انتقال إلى محتوى ذي صلة، ومغادرة إلى مصدر خارجي. لا تسجل البريد أو كلمة المرور أو رقم الهاتف أو عناوين IP في أسماء الأحداث أو خصائصها، ولا تعرض لوحة الإدارة أرقامًا في غياب بيانات فعلية.

الإعلانات ليست عنصرًا مطلوبًا في الإطلاق الوظيفي الأول. قبل تفعيلها يجب أن تتوفر صفحات الخصوصية والشروط، ومراجعة مواضع الإعلان، وعدم وجود تنقل مضلل أو دعوة لنقر الإعلان، ومراجعة أي متطلبات موافقة تنطبق على جمهور الموقع. وتبقى العلامات الإعلانية مفصولة عن بطاقات المحتوى والتنقل.

## 11. التنبيهات الاختيارية

يُصمم نموذج البيانات للتنبيهات من البداية، لكن لا يفعل في أول إصدار عام قبل اختبار الخصوصية والتدفق. يختار المستخدم صراحةً نوع التنبيه والقناة والموضوع أو الموعد، ويستطيع الإيقاف أو التعديل في أي وقت. وتشمل الأنواع المبدئية: نشر دليل مهم، وتذكير بموعد منشور أو مناسبة مرتبطة.

| الخيار | الفائدة | القيد |
|---|---|---|
| تنبيه داخل المنصة | أقل تعقيدًا وأعلى خصوصية | يتطلب عودة المستخدم للموقع. |
| بريد إلكتروني اختياري | مناسب للتنبيهات منخفضة التكرار | يحتاج موافقة موثقة وإدارة اشتراك وإلغاء واضح. |
| إشعار متصفح اختياري | مناسب للتذكير القريب من الموعد | يحتاج إذن الجهاز ولا يرسل من دون قبول صريح. |

## 13. تعريف الإنجاز للإصدار الأول

يعد الإصدار الأول منجزًا عندما تكون Alshafra منصة مستقلة في الاسم والواجهة والبيانات التعريفية؛ وتتوفر فيها أدوات عملية اختبرت نتائجها، وقسم تقويم ومواعيد يعرض المصدر والحالة وتاريخ المراجعة، وأدلة أو مقالات أصلية مترابطة، وإدارة محتوى محمية، وتجربة عامة عربية متجاوبة مفهرسة من HTML أولي. لا يعد الموقع منجزًا لمجرد وجود صفحة رئيسية أو عدد صفحات كبير أو تفعيل إعلان.
