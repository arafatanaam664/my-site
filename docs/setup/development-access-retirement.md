# تعطيل وصول التطوير المؤقت قبل الإطلاق

رمز `DEV_ADMIN_ACCESS_CODE` وسيلة مؤقتة لتسريع التطوير على رابط المعاينة فقط. لا يعد بديلًا دائمًا عن Supabase Auth.

## شرط إطلاق إلزامي

قبل ربط `alshafra.com` أو نشر نسخة إنتاجية، احذف `DEV_ADMIN_ACCESS_CODE` من متغيرات البيئة عبر إدارة الأسرار، ثم أعد تشغيل النسخة وتحقق من الآتي:

1. لا يظهر قسم **دخول التطوير المؤقت** في `/admin`.
2. تعيد `GET /api/admin/development-access` القيمة `enabled: false`.
3. لا يقبل `POST /api/admin/development-access` أي رمز.
4. يظل تسجيل الدخول المعتمد عبر Supabase فقط متاحًا.

سجل هذه النتيجة في قائمة قبول الإطلاق بعد تشغيل endpoint على النطاق النهائي. لا يكفي وجود التوثيق أو إخفاء النموذج وحده؛ يلزم التأكد عمليًا من رفض الرمز قبل نشر النسخة النهائية.

حتى إذا نُسي المتغير بالخطأ، يرفض التطبيق أصل `alshafra.com` صراحةً؛ إذ يقصر وصول التطوير على `localhost` وروابط المعاينة المنتهية بـ`.manus.computer`. يبقى حذف المتغير مطلوبًا لإزالة السطح غير الضروري قبل الإنتاج.
