# إعداد Supabase وCloudflare R2 لمنصة Alshafra

هذا الدليل يجهّز فقط حسابات وبيانات الربط اللازمة للمحتوى والصور والإدارة. **لا ترسل أي مفتاح في المحادثة أو البريد**؛ احتفظ به مؤقتًا في مدير كلمات مرور، ثم أدخله فقط من بطاقة الإدخال الآمنة داخل المشروع عندما أطلبه منك.

> تستخدم Supabase حاليًا مفتاحين حديثين: **Publishable** للمتصفح و**Secret** للخادم. لا نحتاج إلى استخدام مفاتيح `anon` و`service_role` القديمة في البناء الجديد ما لم تكن هناك حاجة توافقية استثنائية.[1]

## 1. إنشاء مشروع Supabase

افتح [Supabase](https://supabase.com/) وأنشئ حسابًا أو سجّل الدخول، ثم اتبع الخطوات الآتية من لوحة التحكم.

| الخطوة | ما تفعله | ملاحظة مهمة |
|---|---|---|
| 1 | اختر المؤسسة (Organization) المناسبة، ثم اضغط **New project**. | استخدم مؤسسة تملكها أنت أو شركتك، لا حسابًا مشتركًا غير موثوق. |
| 2 | اختر اسمًا واضحًا مثل `alshafra-production`. | لا تضع مفاتيح أو بيانات حساسة في الاسم. |
| 3 | أنشئ **Database Password** قوية وفريدة واحفظها في مدير كلمات مرور. | هذه ليست مفتاح API ولا تدخل في بطاقة الربط الحالية. |
| 4 | اختر المنطقة الأقرب إلى جمهورك واحتياجك التنظيمي من الخيارات التي تظهر لك. | لا يمكن تغيير منطقة مشروع قائم ببساطة، لذلك اخترها بوعي. |
| 5 | اضغط **Create new project** وانتظر حتى تكتمل التهيئة. | لا تستخرج المفاتيح قبل ظهور حالة جاهزية المشروع. |

بعد إنشاء المشروع، افتح شاشة المشروع ثم اذهب إلى أحد المسارين التاليين:

* **Integrations → Data API** للحصول على **Project URL**.
* **Settings → API Keys** للحصول على المفاتيح.[1] [2]

## 2. استخراج مفاتيح Supabase الصحيحة

في **Settings → API Keys**، أنشئ مفاتيح حديثة إن لم تكن ظاهرة عبر **Create new API Keys**. ستحتاج القيم التالية فقط:

| المتغير الذي سأطلبه | من أين تنسخه | أين يستخدم | هل هو سري؟ |
|---|---|---|---|
| `SUPABASE_URL` | Project URL من **Integrations → Data API** | الخادم والواجهة بحسب الحاجة | لا يُعامل كمفتاح سري، لكنه يدخل من البطاقة الآمنة للتوحيد. |
| `SUPABASE_PUBLISHABLE_KEY` | قسم **Publishable key** | الواجهة العامة أو لوحة الإدارة مع RLS | يمكن أن يظهر في المتصفح، لكن RLS يجب أن تحمي كل جدول. |
| `SUPABASE_SECRET_KEY` | قسم **Secret keys** | Worker/خدمة خادمية فقط | **سري جدًا**؛ لا يدخل المتصفح ولا Git ولا الدردشة. |

لا تنسخ `service_role` أو `anon` إلا إذا طلبت منك ذلك لاحقًا لحالة توافقية محددة. المفتاح السري يتجاوز سياسات RLS، ولذلك يوضع في البيئة الخادمية فقط.[1]

## 3. إعدادات Supabase التي لا تغيّرها الآن

لا تنشئ الجداول أو سياسات RLS يدويًا الآن؛ سأوفر لك migration قابلة للمراجعة عند بدء مرحلة قاعدة البيانات. لا تعطل RLS، ولا تجعل التخزين أو الجداول عامة، ولا تضف مفاتيح إلى ملف `.env` مرفوع إلى GitHub.

يمكنك لاحقًا مراجعة **Security Advisor** في Supabase، لكن لا تتجاهل أي تنبيه أو تعدله لمجرد اختفائه. المفتاح القابل للنشر ليس طبقة حماية للبيانات؛ الحماية الفعلية تأتي من RLS والسياسات الصحيحة.[1]

## 4. تفعيل Cloudflare R2 وإنشاء حاوية الوسائط

افتح [Cloudflare Dashboard](https://dash.cloudflare.com/) وسجّل الدخول إلى الحساب الذي سيملك النطاق `alshafra.com`. انتقل إلى **Storage & databases → R2 → Overview**.

> تشير وثائق Cloudflare الحالية إلى أن إنشاء مفاتيح R2 يتطلب تفعيل/شراء R2 في الحساب أولًا. راجع شاشة التسعير والتأكيد قبل المتابعة؛ لا أفترض أن الخدمة ستبقى مجانية بلا حدود.[3]

| الخطوة | ما تفعله | الاختيار الموصى به للإطلاق |
|---|---|---|
| 1 | اختر **Create bucket**. | — |
| 2 | اكتب اسم الحاوية: `alshafra-media`. | اسم صغير بحروف إنجليزية وشرطات فقط. |
| 3 | اختر الموقع وخيار التخزين من الخيارات الظاهرة. | استخدم **Standard** للوسائط التي ستُقرأ كثيرًا؛ طبقة الاستخدام المجاني الحالية تخص Standard فقط.[4] |
| 4 | اضغط **Create bucket**. | لا تجعل الحاوية عامة مباشرة في هذه المرحلة. |

### رابط الصور العام

بعد أن يصبح النطاق تحت إدارة Cloudflare، أنشئ نطاقًا فرعيًا مخصصًا مثل `media.alshafra.com` من إعدادات الحاوية/النطاقات العامة، ثم اربطه بالحاوية واتبع تأكيد DNS الظاهر في اللوحة. عند نجاحه تكون قيمة المتغير:

```text
R2_PUBLIC_BASE_URL=https://media.alshafra.com
```

لا تستخدم رابط معاينة مؤقت أو `r2.dev` بوصفه رابط الصور الدائم للإنتاج. إن لم يكن ربط النطاق جاهزًا، اترك هذا المتغير فارغًا مؤقتًا؛ سنفعّل الصور العامة لاحقًا بعد التحقق.

## 5. إنشاء مفاتيح R2 المقيدة

من **R2 → Overview**، ابحث عن قسم **API Tokens** ثم اختر **Manage**، وبعدها أنشئ Token جديدًا.

| الإعداد | القيمة الموصى بها |
|---|---|
| نوع Token | Account API token إن كان الحساب شخصيًا ومملوكًا لك؛ أو User API token إذا أردت أن ينتهي عند إلغاء مستخدم معين. |
| الصلاحية | **Object Read & Write** فقط. |
| النطاق | **Apply to specific buckets only** ثم اختر `alshafra-media` وحدها. |
| ما لا نمنحه | لا تختَر Admin Read & Write ولا كل الحاويات. |

بعد اختيار **Create API Token** ستظهر لك قيمة **Access Key ID** و**Secret Access Key** مرة واحدة فقط. انسخهما إلى مدير كلمات المرور فورًا؛ لا يمكن عرض Secret Access Key من جديد بعد مغادرة الشاشة.[3] [5]

ستحتاج أيضًا إلى **Account ID** وS3 Endpoint. يظهر endpoint بهذا الشكل:

```text
https://<ACCOUNT_ID>.r2.cloudflarestorage.com
```

| المتغير الذي سأطلبه | القيمة المطلوبة |
|---|---|
| `R2_ACCOUNT_ID` | معرّف حساب Cloudflare الظاهر في لوحة الحساب أو داخل endpoint. |
| `R2_ENDPOINT` | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`، من دون إضافة اسم الحاوية. |
| `R2_ACCESS_KEY_ID` | Access Key ID من Token R2. |
| `R2_SECRET_ACCESS_KEY` | Secret Access Key من Token R2. |
| `R2_BUCKET_NAME` | `alshafra-media`. |
| `R2_PUBLIC_BASE_URL` | `https://media.alshafra.com` بعد ربط النطاق الفرعي فقط. |

لا نحتاج إلى إعداد CORS في البداية لأن الرفع سيجري عبر طبقة خادمية موقعة. إذا انتقلنا لاحقًا إلى رفع مباشر من المتصفح، سنضيف CORS بأصل لوحة الإدارة المحدد فقط، لا بعلامة `*`.

## 6. ما تفعله بعد الانتهاء

بعد أن تنشئ المشروع والحاوية والمفاتيح، لا ترسل القيم في الدردشة. اكتب فقط: **«أنشأت Supabase وR2»**. سأفتح بطاقة إدخال آمنة محدثة بالأسماء الحديثة، ويمكنك عندها لصق القيم في حقولها.

إذا ظهر لك طلب تفعيل فوترة R2 أو لم تجد خيار API Tokens، أخبرني باسم الشاشة أو أرسل لقطة تخفي أي مفتاح، وسأرشدك للخطوة التالية.
