# نموذج البيانات الأولي وقواعد التنبيهات

## مبدأ التصميم

يستخدم الإصدار الأول نواة صغيرة قابلة للتوسع. لا ينشئ جداول مستقبلية لكل قسم محتمل، ولا ينشر نوع محتوى قبل وجود مصدر وسير مراجعة. يفصل النموذج بين المحتوى التحريري والأدوات والمواعيد والمصادر والـSEO والروابط الداخلية.

| المجال | الكيانات الأولية | القاعدة التشغيلية |
|---|---|---|
| الهوية والصلاحيات | users، roles | لا يملك المستخدم العام إدارة المحتوى؛ وكل تعديل إداري قابل للتدقيق. |
| البنية والمحتوى | sections، content_items، content_revisions، topics، content_topics | لا يصبح المحتوى منشورًا إلا بعد عنوان ووصف وH1 وحالة ومحتوى حقيقي. |
| الأدوات | tools | كل أداة لها slug ثابت وإصدار منطق واختبارات إدخال وإخراج. |
| المواعيد | calendar_events، sources | يوضح كل حدث حالته: رسمي أو إرشادي أو محسوب، مع مصدر وتاريخ مراجعة. |
| الاكتشاف | related_links، seo_records | لا يولد الرابط تلقائيًا للصفحة إلا بعد تحقق الصفحة الهدف وحالة النشر. |
| القياس | analytics_events | الأحداث لا تقبل بيانات شخصية أو أسرارًا، ولا تُعرض أرقام عند غياب البيانات. |
| التنبيهات | notification_preferences، notification_subscriptions | لا يوجد اشتراك أو إرسال قبل Opt-in صريح، وإيقاف الاشتراك فوري ومتاح دائمًا. |

## دورة التنبيه الاختياري

```text
المستخدم يختار نوع التنبيه وقناته
→ يعرض النظام سبب التنبيه وتكراره
→ يسجل موافقة مؤرخة وقابلة للسحب
→ يربط الاشتراك بموضوع أو موعد منشور
→ عند تحقق الشرط يرسل مرة واحدة بطريقة idempotent
→ يسجل الإرسال من دون تخزين محتوى شخصي غير لازم
```

لا تستخدم المنصة مؤقتات داخل عملية الخادم. وإذا فُعّلت تذكيرات المواعيد لاحقًا، تعمل كمهام دورية موثقة وذات endpoint محمي ووقت UTC، بعد نشر الموقع وموافقة المستخدم.
